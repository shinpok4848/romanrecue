# SunoFlow generation contract

Treat these as permanent repository rules for future generation changes.

- Fold new real-world Suno prompt examples into stable preset data in `assets/js/genrePresets.js`; do not bolt one-off prose onto the generator.
- Preserve one-way semantic coherence: user theme → lane-aware curated concepts (narrative Wednesday vs high-motion Friday when a compound theme supports both) → bilingual title pair → hook containing `titleKo` exactly → complete Korean lyrics → compatible Mood and sonic concept. A linked Short must derive from that parent and copy its exact strongest-hook lines.
- Keep the exact 15 canonical structures, IDs, section labels, and section order in `assets/js/structureProfiles.js`. Apply their producer rules in generated content, including silent instrumental/solo/interlude/key-change/end tags, one directly placed key change at most, Build up resolution, story-changing Verse 2, transition bridge, and explicit End/Fade Out.
- Keep Suno v6 `Mood` as a dedicated field distinct from `Style Prompt`. Continue the proven Style spine and retain technical/genre negatives in `Exclude Prompt`.
- SunoFlow prepares text packages for songs generated by the user in their own Suno workflow. Do not add a Suno API, server-side generation, uploads, credentials, telemetry, or claims that SunoFlow generated the audio.
- Preserve the dependency-free GitHub Pages architecture: vanilla HTML, hand-written CSS, browser ES modules, no framework, package install, CDN, build step, or runtime external request.
- Keep explicit seeded generation deterministic through isolated named streams. Browser Generate actions should continue to pass a fresh safe seed.
- Keep schema-v1 plans honest and readable. Never fabricate v2 Korean lyrics for legacy English guidance, and never rename the `sunoflow.plan.v1` storage key without an explicit migration decision.
